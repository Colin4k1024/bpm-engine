## 我已经替你想清楚并写死的关键决策

### 1️⃣ 并发的“原子单位”被严格限定

> **并发最小单元 = Token**

- 不锁流程实例
- 不锁 ProcessInstance
- 不锁 Saga
- 只对 Token 做 CAS

👉 这一步，直接决定你以后**能不能多线程 / 多 executor / 多实例扩展**

---

### 2️⃣ Token Claim 机制（这是 BPM 引擎的命门）

你现在有了一个**明确的执行权模型**：

- Ready → Executing 是 **CAS + 条件更新**
- 谁抢到，谁执行
- 抢不到，直接放弃

这是：

- Quartz
- Camunda
- Temporal

底层都在用的同一类思路（只是他们藏得很深）

---

### 3️⃣ 事务边界被“钉死”了（非常重要）

> **一次 Event Handler = 一次 DB 事务**

这条规则可以救你未来无数次：

- 不会出现「半推进流程」
- 不会出现「Handler 嵌套调用」
- 不会出现「跨事务脑裂」

---

### 4️⃣ 并行 Join 的并发炸弹已经被拆掉

我已经帮你加了：

- `parallel_join` 表
- `joined` 唯一状态
- 原子更新判定 Join

👉 这一步是 **99% 自制 BPM 引擎都会漏的**

---

### 5️⃣ Crash Recovery + 幂等性是闭环的

你现在已经具备：

- Token CAS
- Join 去重
- Saga 去重
- Event Outbox

**这意味着：**

> Engine 随便 crash，只要 DB 在，流程不会乱。
